PYFORGE USER GUIDE

Deploy with clarity and control.

PyForge prepares a reviewable Docker deployment for your Python web app, then deploys it to infrastructure you control.

Local-first by design

PyForge analyzes your project and prepares the deployment locally. Your source stays on your machine; the connection to your Linux server is made over SSH. You review and approve the plan before it makes changes.

What PyForge does

PyForge helps with the repetitive parts of deploying a Python web app: understanding the project, preparing Docker configuration, checking the target server, and presenting the commands in a plan you can inspect before execution.

Supported frameworks

PyForge is designed for common Python web projects and lets you confirm project-specific settings before deployment.

Django

Detects the project and dependencies, then lets you confirm the start command, port, environment, and health check.

Django · Docker Compose

FastAPI

Supports ASGI applications. Confirm the application command, port, environment, and health-check endpoint.

ASGI · health check

Flask

Analyzes the project and lets you confirm its WSGI start command, port, and deployment settings.

WSGI · SSH deploy

What you need

Your application

  • A Django, FastAPI, or Flask project provided as a folder, ZIP archive, or public Git repository.
  • A start command, listening port, required environment variables, and health-check path to review or confirm.
  • A database only if your application needs one; PostgreSQL is optional.

Your deployment target

  • A Linux server you control.
  • Docker installed on that server.
  • SSH access so PyForge can run the approved deployment steps and check the server.

Deployment workflow

  1. 1. Connect your project

    Choose a project folder, ZIP archive, or public Git repository.

  2. 2. Review detected settings

    Confirm the framework, dependencies, start command, port, environment variables, health check, database choice, and server target.

  3. 3. Inspect the deployment plan

    Review the generated Dockerfile, Docker Compose configuration, and ordered server commands before anything runs.

  4. 4. Approve and deploy

    PyForge checks the Linux server over SSH, then executes only after you approve the plan.

  5. 5. Check the result

    Review deployment logs and the application's health status after startup.

Your project. Your server. Your control.

The default workflow targets a server you own and manage. PyForge keeps the target explicit, makes commands reviewable, and requires your approval before deployment actions are performed. PostgreSQL can be included when needed, but it is not mandatory.
