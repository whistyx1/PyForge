PLANNED CAPABILITIES

Practical deployment machinery we are building.

These features are planned; the current site offers an interactive setup demo, not project analysis or deployment.

  • Project analysis

    Detect the Python project and confirm its framework, dependencies, start command, and health check.

  • Docker generation

    Generate a Dockerfile and Docker Compose configuration for the reviewed deployment.

  • SSH server checks

    Check your Linux server over SSH and confirm Docker is installed before deployment.

  • Reviewable deployment plans

    Show each command for approval before making changes to your server.

  • Optional PostgreSQL

    Add PostgreSQL when a project needs it, without making a database mandatory.

  • Logs and health checks

    Display deployment logs and application health status after startup.

PRACTICAL ANSWERS

Questions about the planned deployment workflow.

The intended model uses local tooling, reviewable commands, SSH, and infrastructure you own. The current site is a setup preview.

  • Where does PyForge run?

    The plan is for PyForge to run locally, analyze your project, and connect to your server over SSH. The current preview only runs in your browser.

  • What server do I need?

    The planned deployment workflow will need a Linux server with Docker installed. PyForge does not check visitor servers yet.

  • Can I review commands before they run?

    Not yet. A future version will show the deployment plan and commands for approval before changing your server.

  • Does PyForge generate Docker configuration?

    Not yet. Generating a Dockerfile and Docker Compose configuration is planned.

  • Is PostgreSQL required?

    No. Optional PostgreSQL is planned for projects that need it.

  • Which Python frameworks are supported?

    Django, FastAPI, and Flask are the target frameworks; project analysis and deployment are still planned.
